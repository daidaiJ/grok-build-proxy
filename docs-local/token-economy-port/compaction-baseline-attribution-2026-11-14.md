# 压缩后基线多档归因（2026-11-14）

> 只读诊断。数据：本机 `~/.grok/sessions/**/compaction_checkpoints/*.json`（19 份，
> 2026-10-30 → 2026-11-14）、`~/.grok/cache/model-usage.jsonl`、`tool_definitions.json`。
> 复现：`scripts-local/compaction_baseline_audit.py`。

## 1. 结论

压缩后的首轮 prompt 不是“随机 17/26/40/66k 四档”，而是同一个公式的结果：

```
基线 = system prompt + 工具声明 + user_info（规则/AGENTS.md）
     + 当前 user_query + 压缩摘要 + 技能清单
```

- **没有任何保留轮次**：19 份检查点全部是同样的 5 条消息（system、user_info、
  user_query、summary、技能清单），因此“保留最近几轮”不是变量。
- 压缩模式/详细度、two-pass prefire 也不是变量：本机 two-pass 默认关闭，检查点形态一致。
- **档位差距的主因是 `user_info`**：当前 normal 档 0.4–4.8k token；旧档 13–14k；
  11-13 治理前的 AGENTS.md 是 **37.1k token（74.3k 字符）**，直接把基线推到 66–68k。
- 摘要长度只在 2.4–8.4k 之间波动；技能清单 3.7–8.4k；system 1.8–3.5k；
  工具声明约 11.5k（26 个工具）。
- 11-13 的 AGENTS.md 治理已把 66k 档消掉：11-14 的三个会话回落到 26.3–30.1k。
  剩余可选空间只有 summary（约 5–6k）和工具声明（约 11.5k，零调用子集 6.2k）；
  前者压小会丢细节，后者是独立的“工具延迟声明”任务，不属于压缩基线。

**判定：压缩后基线本身不再优化。** 唯一值得动的是工具声明面。

## 3. 为什么 66k 档消失了

`user_info` 里的 `<rules>` 块来自 `AGENTS.md`。11-13 之前该文件累积了全部
TODO/Handoff 历史（74.3k 字符）；治理把过程记录移入 `docs-local/` 后，
11-14 会话的 `user_info` 降到 438–4,816 token，压缩基线随之回到 26–30k。
这部分是**一次性已完成**的优化，不需要再做。
