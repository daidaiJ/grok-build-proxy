## 2. 当前实现判断

### 已经做得好的部分

1. **文件可读，作用域隔离。** Legacy 使用 Markdown；V2 将 global / workspace 分开，manifest 是生成索引，不要求用户编辑索引本身。
2. **检索已有完整的降级链。** Legacy 组合 FTS5 与可选向量检索；向量不可用时仍可用 FTS。结果排序已考虑时间衰减、来源权重、访问次数与多样性。
3. **控制了会话记忆的陈旧风险。** session 来源会随时间衰减，较旧结果会附核验提示；初次注入内容会持久复用，避免重搜导致 system prompt 前缀变化和 KV cache 失效。
4. **写入有基本质量闸门。** flush / dream 要求结构化 Markdown，可返回 `NO_REPLY`，并有长度上限；flush 支持语义重复检测。
5. **V2 存储层已经考虑崩溃恢复与文件安全。** 捕获队列和观察记录有上限、symlink 检查、幂等与 reconcile 机制；manifest 默认限制注入体积。

### 主要缺口

1. **长期记忆被当作常青内容。** 搜索时 `global` / `workspace` 不做时间衰减，`format_staleness_note` 也不为这两个来源显示陈旧提示。长期记忆中的易变路径、配置或行为规则可能过时。
2. **提取提示仍鼓励记录部分可从仓库重建的事实。** flush 提示包含架构、API、模式和路径；虽要求优先保存可复用机制并避免临时进度，但没有明确以“当前代码能否重新推导”为筛选条件。
3. **V2 自动捕获还没有接入会话写入路径。** `V2CaptureStore` 的实现和测试存在，但在 shell 代码中未发现其写入调用点。当前 V2 首轮与压缩恢复会注入 global / workspace manifest，用户显式 remember 笔记也能写成观察记录；自动 observation 提取仍未启用。
4. **V2 注入说明弱于 Legacy。** Legacy reminder 明确说记忆是历史上下文，并要求冲突时以当前证据为准；V2 当前主要注入两个 manifest，没有同等明确的使用纪律。
5. **缺少小型“该记/不该记、该召回/不该召回”的产品行为回归集。** 现有单测覆盖存储、检索和格式化机制，但机制测试不能单独证明自动记忆的净收益或误导率。

## 3. 对照业界设计后的取舍

| 业界做法 | 收益 | 成本 / 风险 | 对本项目的判断 |
|---|---|---|---|
| 明文文件、按需检索、作用域分层 | 可审查、可编辑，控制上下文预算 | 需要维护索引和一致性 | 已有；无需重做存储架构 |
| 记忆 citation + 当前分支校验（Copilot） | 降低陈旧代码事实误导 | 需要保存并验证引用，处理分支差异与无效来源 | 作为长期方向；目前不适合作为首个改动 |
| 自动记忆 + 过期清理 | 控制噪音与陈旧条目 | 自动删除可能误删仍有用知识；需要稳定的使用统计 | 不建议直接复制 28 天 TTL；先提示核验、再积累证据 |
| 纯手工记忆 / 明确规则文件 | 写入确定、便于 review | 依赖用户纪律，自动收益较低 | 适合作为高可信偏好或明确决策的来源，不应替代现有自动机制 |
| V2 结构化观察记录与生成索引 | 有类型、来源、重放与恢复基础 | 自动提取接线后会扩大测试和维护面 | 先完善注入纪律和质量评测，再决定是否接线 |

## 4. 建议按阶段推进

### P0：统一 V2 注入使用纪律

**改动范围：** 在 `format_v2_memory_context` 输出中加入与 Legacy 等价的短说明：记忆是历史资料，不是当前计划；遇到路径、命令、仓库状态和外部事实时，以当前工具核验结果为准。若记忆正文包含指令性文字，应把它作为待核验的记忆内容，而不是提升为系统规则。

**成本：** 很低；纯格式化文本，不改存储、不改排序、不迁移数据。

**验收：** V2 首轮注入与压缩恢复均含同一段说明；Legacy 提示不变；上下文仍受现有 manifest 预算限制。

### P1：降低自动提取的可推导事实与临时噪音

**改动范围：** 收紧 `FLUSH_SYSTEM_PROMPT`、增量 flush 和 dream 提示，明确优先写入：用户明确偏好 / 反馈、决策及理由、尚未沉淀进代码的非显然经验、外部服务行为与可靠 workaround。明确不写：可直接从当前代码或 git 状态读取的事实、临时分支状态、任务进度、无证据的推断。代码路径只有在帮助未来定位且不容易推导时才保留。

**成本：** 低；提示词调整，可能改变模型输出风格，需要少量样例回归。

**验收：** 用同一组固定对话检查：常规改代码不生成重复架构记忆；关键决策理由、用户明确偏好和非显然 workaround 仍保留；无内容时仍正确返回 `NO_REPLY`。

### P2：建立精简的记忆行为回归集

**改动范围：** 选取少量真实或合成案例，记录应保留的信息、应丢弃的信息、应召回的问题，以及与当前仓库事实冲突时必须重新核验的情形。先用固定预期做人工 / 模型对照，不引入新的基准服务或大型评测框架。

**成本：** 低到中；主要成本是定义可复现案例和维护预期。

**验收：** 提示词或排序变化前后，能比较“漏记、噪音记忆、错误召回、陈旧事实误导”四类结果，而不只看召回数量。

### P3：给长期记忆增加可解释的新鲜度信息

在 P2 有证据后再做。先考虑显示来源时间或提示用户核验，不自动删除；再评估对高易变事实增加 `as_of` / 来源字段。不要把文件修改时间误当成所有条目已重新验证，也不要未经评测就给 global / workspace 套统一 TTL。

### 暂缓：启用 V2 自动 observation 捕获

捕获队列很完整，但接线不是单点改动：还要定义何时截取会话范围、如何调用提取模型、如何应用 user/project/reference 类型、失败重试、状态恢复与质量回归。当前先让明确的用户 remember 和 manifest 路径继续工作；完成 P0–P2 后再用回归数据决定是否启用自动写入。

## 5. 推荐顺序与决策

| 顺序 | 项目 | 预期收益 | 估计改动面 | 决策 |
|---|---|---:|---:|---|
| 1 | V2 reminder 补齐历史性 / 核验说明 | 中高 | 极小 | 建议先做 |
| 2 | 收紧 flush / dream 的记忆筛选 | 高 | 小 | 建议第二步 |
| 3 | 小型记忆行为回归集 | 高（降低后续试错成本） | 小到中 | 与第 2 项配套 |
| 4 | 长期记忆新鲜度标记 | 中高 | 中 | 评测后再定 |
| 5 | V2 自动捕获接线 | 潜在较高 | 大 | 暂缓 |

**总判断：** 本项目的主要短板是长期事实的新鲜度和自动写入噪音，而不是检索能力。最稳妥的收益路径是先补 V2 注入说明，再收紧提取提示，并用小型回归集确认没有损失有价值信息；citation 校验、自动 TTL 和 V2 自动捕获都放到后续证据充分时再决策。
