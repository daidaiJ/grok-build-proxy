# issues 台账（grok-build-proxy 使用问题专题目录）

> 用途：登记**使用中发现的 bug 与行为问题**——上游源码的问题、本地补丁引入的
> 问题各占一类，issue 文件内先判归属再排查。机制深读、移植盘点类文档仍放
> `docs-local/` 平级文件，不进本目录。

## 约定

- **一 issue 一文件**：文件名 `YYYY-MM-DD-<短横线英文 slug>.md`（日期 = 发现日）。
- 文件头必填：`状态` / `严重度` / `发现方式` / `环境`（分支 + commit）。
- **状态机**：`open（待复现/待排查）` → `reproduced（已复现，根因定位中）`
  → `fixed（已修，登记 PATCHES.md）` / `upstream（确属上游，待上报或放弃）`
  / `wontfix（拍板不修，留档）`。
- **严重度**：P0 崩溃/丢数据 · P1 功能不可用 · P2 功能可用但显示/行为错误 ·
  P3 打磨项。
- **归属判定**：每个 issue 必须回答「本地补丁嫌疑还是上游自带」——先对照
  `PATCHES.md` 的本地补丁清单与 `SOURCE_REV`，能用 bypass/直连复测的就复测，
  再定上报或自修。
- 排查线索一律标注 `未证实假设`，锚到 `file:line`；修完把结论回填 issue 文件
  （不改写历史，追加「结论」小节）。
